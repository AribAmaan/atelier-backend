# Backend Debug Audit — 2026-11-21

## Scope

Audited the `atelier-backend-main19-adult-scene-flexible` backend archive, focusing on the mature-scene detector, prompt assembly, roleplay input/agency rules, server-side scene-state wiring, and the related regression tests. Existing application features and provider order were not intentionally redesigned.

## Fixes applied

1. **Assistant text is not user intent.** Mature-scene activation and continuation are now based on user-authored turns, not explicit wording generated by the assistant. Assistant text cannot revive a scene after the user has withdrawn consent.
2. **Withdrawal is a hard boundary.** Added coverage for natural refusal/discomfort language, changed mind, spoken and observable physical withdrawal, and narrator-described discomfort. A later short continuation does not undo an earlier user boundary by itself.
3. **Pacing is not automatically refusal.** `wait`, `pause`, `hold on`, `slow down`, and mild nervousness/uncertainty remain pacing cues. The prompt directs the character to pause or adjust the beat as requested. Clear refusal/withdrawal still ends that intimate action.
4. **Private thoughts stay private.** Private narration is not used as an invitation or as observable physical withdrawal. Observable narrated discomfort/withdrawal is still respected.
5. **False-positive reduction.** Added medical/non-erotic anatomy exclusions and tests for negative instructions such as “avoid explicit content”, “keep it romantic”, and “fade to black”.
6. **Natural contractions.** Fixed continuation matching for phrases such as “I'm nervous” and “I'm not sure”.
7. **Prompt/cache consistency.** The prompt now has separate inactive/active scene states, cache-version keys were bumped, and repeated roleplay-agency wording was compressed while preserving the user's meaningful choices, dialogue, thoughts, and consent.
8. **Stale tests corrected.** Updated assertions that still expected the pre-simplification prompt wording and expanded the mature-scene regression suite.

## Known limitation — character age is not a structured field

The Prisma `Character` model has `isExplicit` but no structured character-age field. The prompt says every participant must be clearly established as 18+ and that unknown, ambiguous, or under-18 ages remain non-explicit. That is currently a model/prompt instruction, **not deterministic backend age verification**. This patch does not add a schema migration or claim otherwise. A hard age check would require a structured age/adult-status field, a trusted way to populate it, and a server-side guard before constructing the active mature-scene prompt.
